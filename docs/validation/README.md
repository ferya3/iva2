# پروتکل اعتبارسنجی فنی و علمی

> اجرای ۱۰۰ باره بدون خطای JavaScript، اثبات دقت روان‌سنجی نیست. این سند معیارهای پذیرش را **پیش از** جمع‌آوری داده تعریف می‌کند.

## ۱. ماتریس تست

## ۲. اعتبارسنجی زمانی روی سخت‌افزار

**تجهیزات:** فوتودیود روی گوشه صفحه (مربع سفید هم‌زمان با محرک)، میکروفون/کارت صدا با ورودی line برای loopback،
میکروکنترلر (مثلاً Arduino/Teensy) برای ثبت لبه‌ها با دقت ≤ ۰٫۱ms، و دکمه سخت‌افزاری برای شبیه‌سازی پاسخ.

**ماتریس سخت‌افزار (حداقل):** ۳ لپ‌تاپ + ۳ دسکتاپ ویندوز ۱۰/۱۱، کارت گرافیک مجتمع و مجزا، نمایشگر ۶۰ و ۱۴۴Hz،
خروجی صدای داخلی، USB و هدفون بلوتوث (انتظار: رد در کالیبراسیون).

**روش:** برای هر پیکربندی ۵۰۰ محرک دیداری و ۵۰۰ شنیداری؛ ثبت `actual_time_ms` موتور در برابر زمان فیزیکی.

**معیار پذیرش پیشنهادی (قابل تنظیم در `validation_rules`):**

| معیار                        | دیداری                                                             | شنیداری    |
| ---------------------------- | ------------------------------------------------------------------ | ---------- |
| میانگین خطای ثابت (bias)     | قابل جبران؛ با `presentationLatencyFrames`/جبران latency تنظیم شود | قابل جبران |
| انحراف معیار خطا (jitter)    | ≤ ۲ms                                                              | ≤ ۱ms      |
| صدک ۹۹ خطای مطلق پس از جبران | ≤ نیم فریم (۸٫۳ms در ۶۰Hz)                                         | ≤ ۵ms      |
| محرک از دست رفته             | ۰ در شرایط عادی                                                    | ۰          |

خروجی: جدول توزیع خطا برای هر پیکربندی + مقادیر جبران‌سازی ثبت‌شده در نسخه پروتکل.

## ۳. کنترل کیفیت هر اجرا (پیاده‌سازی‌شده)

`packages/scoring-engine/src/quality.ts` — هر کنترل آستانه هشدار و بحرانی صریح و نسخه‌دار دارد.
یک افت فریم به‌تنهایی اجرا را باطل نمی‌کند؛ فقط نرخ‌هایی که از معیار پروتکل عبور کنند.

| کنترل                                                    | خروجی                       |
| -------------------------------------------------------- | --------------------------- |
| شکاف sequence / ترتیب زمانی نامعتبر / نبود شروع یا پایان | بحرانی → `invalid`          |
| توقف آزمون پیش از پایان                                  | بحرانی                      |
| نسبت onset دیرهنگام / محرک ارائه‌نشده                    | هشدار یا بحرانی بر اساس نرخ |
| افت فریم در دقیقه                                        | هشدار/بحرانی                |
| مخفی شدن پنجره / از دست رفتن فوکوس                       | هشدار؛ مدت طولانی → بحرانی  |
| خطای صدا                                                 | هشدار/بحرانی                |
| نرخ omission بسیار بالا                                  | هشدار درگیری/درک دستورالعمل |

## ۴. مسیر اعتبارسنجی علمی (مستقل از MVP فنی)

1. طراحی پروتکل علمی با متخصص روان‌سنجی (نسخه جدید آزمون با `is_clinical=false` تا پایان مطالعه).
2. اخذ مجوز کمیته اخلاق و مراجع ذی‌صلاح؛ فرم رضایت آگاهانه (نسخه‌دار در جدول `consents`).
3. پایلوت (n≈۳۰) برای قابلیت اجرا و وضوح دستورالعمل فارسی.
4. پایایی: بازآزمایی (فاصله ۲–۴ هفته، ICC)، همسانی درونی بلوک‌ها.
5. روایی: همگرا/واگرا با ابزارهای معتبر، روایی گروه‌های شناخته‌شده.
6. هنجاریابی: نمونه طبقه‌بندی‌شده بر اساس سن، جنس، تحصیلات و منطقه؛ جداول نمره استاندارد → `scoring_versions` جدید.
7. فقط پس از این مراحل، نسخه‌ای با `is_clinical=true` منتشر شود.

> پروتکل نمایشی `demo-cpt` یک تکلیف Go/No-Go عمومی برای اعتبارسنجی فنی است و هیچ آزمون تجاری (از جمله IVA-2) را بازتولید نمی‌کند.
